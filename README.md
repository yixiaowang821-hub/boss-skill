# 求职沟通助手 · job-communication-coach

一个用于招聘沟通的中文 Codex Skill：结合简历、岗位 JD 和真实聊天记录，判断当前该回应什么，并生成由用户审阅、人工发送的自然回复。

当前初版由技能指令和界面元数据组成。它依靠宿主 Codex 的模型与已获授权的读取能力工作，仓库内没有独立运行的网页应用、后端服务或自动发消息程序。

## 项目解决什么问题

招聘沟通中，通用模板容易重复开场介绍、漏答 HR 的问题，或者把“已读未回复”一律解释为拒绝或无限等待。本项目把已验证的沟通偏好整理为可复用的流程：

1. 先读实际消息和岗位要求，再决定回复目标。
2. 区分简历已体现的经历、未经核验的能力和信息缺口。
3. 用真实、具体的新信息推进交流，避免夸大、重复和催促。
4. 保留用户对材料上传、消息发送及面试安排的决定权。

这些规则不能保证获得回复、面试或录用；匹配分析也不代表录用概率。

## 主要功能

| 功能 | 当前实现 |
| --- | --- |
| 沟通阶段识别 | 识别首次招呼、已读未回复、HR询问、材料补充、面试邀约、明确拒绝等阶段 |
| JD与简历对照 | 区分直接要求、优先项、加分项和标签；区分要求覆盖程度与证据核验状态 |
| 针对问题回复 | 优先回答出勤、周期、到岗、薪资、工具经验等实际问题 |
| 主动跟进分析 | 结合新增信息价值、时间和已发送次数判断是否值得补充；不会自动发送 |
| 自然话术 | 默认生成一版简短中文草稿，正常学生口吻，不堆砌技术和自我介绍 |
| 迟回复与拒绝处理 | 符合迟回复条件时先简短致歉；明确拒绝后仅感谢和祝福 |
| 材料不足处理 | 看不清的截图标为“截图无法辨认”；缺失个人事实时先确认，不自行补写 |
| 异地及线上沟通 | 不替用户承诺未确认的城市或到岗安排，可按用户意愿争取先线上沟通 |

### 当前规则中的关键偏好

- 不主动提年级、毕业时间；对方明确询问或涉及真实资格条件时如实回应。
- 可以介绍相关项目，但不默认添加“可以展示代码/项目/演示”。
- 不主动问“是否接受某届”“是否考虑实习6个月”，直接说明已确认安排。
- 回复间隔超过5小时，或在用户当地晚间回复时，先简短致歉；不编造迟回复原因。
- 已读、无新回复且距发送超过5分钟时，在岗位仍值得争取、没有明确拒绝等冲突的前提下进入主动分析。这是个人偏好，不是通用招聘建议或平台规则。
- 主动跟进必须有新增价值；连续两次主动跟进后仍无回复，建议停止追加。
- 明确拒绝后直接感谢和祝福，不再追问原因或继续争取。

完整规则以 [SKILL.md](SKILL.md) 为准。用户在当前会话中的最新明确指令优先于默认偏好。

## 安装方法

### 使用前提

- 使用能够加载本地 Skills 的 Codex 环境。
- 获取本项目文件夹，确保根目录包含 `SKILL.md` 和 `agents/openai.yaml`。
- 本项目本身无需单独配置 API Key，也没有 `npm install`、`pip install` 或启动服务步骤；模型、登录和费用由宿主环境处理。
- 读取实时招聘网页还需要宿主提供对应的只读能力及用户授权。安装 Skill 不会自动安装浏览器扩展、连接招聘账号或取得页面权限；也可以直接提供文字和截图分析。

### Windows PowerShell 本地安装

以下以官方当前文档列出的用户级目录 `$HOME/.agents/skills` 为例。请先进入下载或克隆后的项目根目录，再执行：

```powershell
$sourcePath = (Get-Location).Path
$skillRoot = Join-Path $env:USERPROFILE '.agents\skills'
$targetPath = Join-Path $skillRoot 'job-communication-coach'
$requiredFiles = @('LICENSE', 'README.md', 'SKILL.md', 'agents\openai.yaml')

foreach ($relativePath in $requiredFiles) {
    if (-not (Test-Path -LiteralPath (Join-Path $sourcePath $relativePath) -PathType Leaf)) {
        throw "Missing file: $relativePath. Run this from the project root."
    }
}

if (Test-Path -LiteralPath $targetPath) {
    throw "Target already exists: $targetPath. Review and back up the installed skill before updating."
}

New-Item -ItemType Directory -Path $skillRoot -Force | Out-Null
New-Item -ItemType Directory -Path $targetPath | Out-Null
New-Item -ItemType Directory -Path (Join-Path $targetPath 'agents') | Out-Null

foreach ($relativePath in $requiredFiles) {
    Copy-Item -LiteralPath (Join-Path $sourcePath $relativePath) -Destination (Join-Path $targetPath $relativePath) -ErrorAction Stop
}

Get-ChildItem -LiteralPath $targetPath -Recurse
```

此命令只复制上述四个项目文件，不会把 Git 仓库元数据或其他本地文件复制到技能目录。目标存在时会停止，不自动覆盖。

**本机路径说明：**创建此初版时，本机已经从 `C:\Users\Administrator\.codex\skills\job-communication-coach` 发现了技能。这个路径是已核对的本机现状，不作为所有 Codex 环境的安装路径保证。若你的环境使用已配置的其他技能目录，请把命令中的 `$skillRoot` 改为实际目录；避免在多个目录重复安装同名技能。

官方当前还支持项目级 `.agents/skills` 目录。安装发现与更新行为请参阅 [OpenAI 官方 Build skills 文档](https://learn.chatgpt.com/docs/build-skills)。本README安装约定核对日期：2026-10-15。

### 确认安装

确认目标目录下能看到 `SKILL.md` 和 `agents/openai.yaml`，再在宿主支持的技能选择器中确认 `job-communication-coach` 可用。官方文档说明 Codex 会检测技能变化；若未出现，重启 Codex 后再检查。文件存在、结构校验通过，不等于所有场景已完成功能验证。

## 使用方法

### 1. 准备输入材料

按当前任务提供相关材料，不必每次重复已经确认且仍有效的信息：

- 简历或明确的经历事实，尤其是本人贡献与工具使用情况。
- 目标岗位JD、卡片或清晰截图，并说明哪些内容已经完整读取。
- 当前HR的真实消息和已发送消息，包含可核对的日期、时间和已读/送达状态。
- 已确认的实习安排、求职方向、城市和沟通偏好。
- 本次目标，例如回答问题、分析匹配、准备一次跟进或感谢收尾。

### 2. 调用技能

在支持 `$` 技能调用的 Codex 界面中使用：

```text
$job-communication-coach
请结合我提供的JD、简历和聊天记录，判断当前该回复什么，生成一版简短自然的草稿。仅分析，不输入或发送。
```

若界面提供技能选择器，也可以选中“求职沟通助手”。具体入口以宿主界面为准。

读取当前网页时应明确范围，例如：

```text
$job-communication-coach
只读当前已经展开的HR会话，不点击、不滚动、不切换其他HR。先确认对方的问题，再生成回复草稿。
```

没有网页读取能力时，改为粘贴聊天原文和JD，或提供截图。技能不应把旧会话冒充成当前页面。

### 3. 审阅后人工发送

普通回复通常输出简短判断和一版草稿。要求完整分析时，可输出状态、事实依据、匹配缺口、行动选择及新增信息价值。需要关键事实时，先向用户确认。

所有话术都是候选草稿，由用户核对后人工发送。用户认可草稿不代表授权模型输入、发送、投递、上传材料或接受面试安排。

### 4. 复用到其他求职者

当前 `SKILL.md` 包含一份截至2026-10-15确认的个人条件快照，包括实习周期、出勤、到岗、城市及求职方向。其他使用者应先修改“候选人条件快照”，或在当前会话中明确提供替代资料。

不要默认套用作者的“6个月、每周5天、约一周到岗”等安排。年级、毕业时间、项目贡献和薪资等信息均应按实际情况处理。

## 输入输出示例

以下为规则说明示例，不是真实聊天记录，也不是固定输出或自动化实测结果。实际回复应随事实调整。

### 示例一：回答实习安排，并处理迟回复

**输入**

```text
HR于2026-10-15 09:00（北京时间）询问：每周能实习几天、实习多久、最快什么时候到岗？
当前时间：2026-10-15 16:00（北京时间）。
本人确认：连续6个月、每周5天，沟通确认后约一周到岗。
此前只发送过默认招呼，尚未说明这些安排。
请生成回复，不发送。
```

**输出示例**

> 对方询问实习安排，回复间隔已超过5小时，先简短致歉。
>
> 您好，不好意思回复晚了。我每周可以实习5天，能连续实习6个月，沟通确认后约一周到岗。方便的话，也希望能约个时间进一步聊聊岗位。
>
> 仅为草稿，未输入或发送。

### 示例二：已读后补充一个新项目事实

**输入**

```text
岗位：Java后端实习，正文要求接口开发、MySQL和Redis基础。
本人确认：参与过电商项目，项目中有Redis预扣库存和异步下单；未确认这些模块是否全部由本人独立完成。
已经告诉HR：实习周期、每周出勤、到岗时间；没有介绍过具体项目功能。
最新消息于2026-10-15 14:00发送，显示已读；当前14:10，没有新回复。
已主动跟进1次。无明确拒绝、关闭或资格冲突信号。
请分析下一次跟进，并生成一版草稿，不发送。
```

**输出示例**

> 已读且距发送超过5分钟，可进入主动分析。本次补充一个与Redis要求相关的项目事实；若人工发送后仍无回复，即达到两次主动跟进上限，不继续追加。
>
> 您好，看到您已读了消息，想再补充一个项目细节：我之前参与的电商项目涉及Redis预扣库存和异步下单，跟岗位的后端方向比较相关。我挺希望争取这次实习，方便的话，想约个时间和您聊聊具体项目。
>
> 仅为草稿，未输入或发送。

### 示例三：明确拒绝后感谢收尾

**输入**

```text
HR于10:00明确回复：看过简历后觉得与岗位不太匹配，祝你求职顺利。
当前10:10，请帮我回复。
```

**输出示例**

> 对方已明确拒绝，直接感谢和祝福，不追问原因或继续争取。
>
> 好的，谢谢您看我的简历，也感谢您的回复。祝您工作顺利，早日找到合适的人选！
>
> 仅为草稿，未输入或发送。

### 示例四：工具经验尚未确认

**输入**

```text
HR询问：uni-app、HBuilder和微信开发者工具都会吗？笔试会考。
简历项目列有uni-app和微信小程序，但本人实际操作范围尚未确认。
```

**输出示例**

> 先确认你分别使用过哪些工具，以及能否独立运行、调试项目。项目技术栈不能直接证明三款工具都能熟练操作；确认前不替你回复“都会”。

## 当前边界与验证状态

- 当前是指令型初版，没有仓库内的安装脚本、自动化测试套件、模型API封装或浏览器插件。
- 技能不自行获取完整简历或历史聊天；需要用户提供，或由宿主在授权范围内读取。
- 结构校验只检查技能文件格式，不证明模型在所有场景都会正确决策。
- 话术、匹配结果和跟进建议均需人工审阅；本项目不承诺招聘效果。
- 行为更新以 `SKILL.md` 为准，界面名称以 `agents/openai.yaml` 为准；修改规则后应同步检查本文示例是否仍成立。
